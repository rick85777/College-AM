# 信息源可靠性与合规：官方源清单、抓取边界与真实性保障机制

> 审计口径：本文全部 URL 于 **2026-11-24** 由 web_fetch 实际访问。✅=HTTP 200 且正文可解析；⚠️=可访问但需 JS 渲染或仅返回壳页；❌=访问失败（注明原因）。**本文不写任何报名时间与费用金额**——这类字段只能以抓取当时的 L1 原文为准，写死在文档里的数字会变成下一次的错误源。

---

## 0. 五条结论

1. **官方源可抓性远好于预期，结构化程度几乎为零**。NEEA 各子站公告页是纯静态 HTML，带发布时间与完整正文；研招目录库、蓝桥杯、国聘、华为认证则全是 SPA 壳。
2. **没有任何源提供 RSS 或公开 API**。抽查 16 个源首页，0 feed、0 API，"自动更新"只能靠**列表页增量 diff**。
3. **robots 不是障碍，ToS 才是雷区**。雅思托福报名站 Disallow: / 全站禁抓；挑战杯封禁 GPTBot/ClaudeBot/CCBot 等 AI 爬虫，只能人工录入。
4. **资质风险被低估**：做考试竞赛索引不构成新闻信息服务许可事项，但**一做招聘投递闭环就撞上人力资源服务许可证**。
5. **保真的核心不是"抓得准"，是"敢展示不确定性"**：置信度 + 三档阈值 + L1 熔断。

## 1. 分层信源体系

分层决定的是**能否自动发布、多久复核、何时判死**。

| 层级 | 定义与代表 | 采信规则 | 复核频率 | 失效判定 |
|---|---|---|---|---|
| **L1 官方** | 主办方一手发布口：教育部教育考试院各子站、人社部人事考试中心、工信部教考中心、中注协、财政部会计评价中心、竞赛组委会 | **唯一可直接支撑"报名时间/费用/考试日期"的层级**；须留存原文快照与抓取时间 | 报名季每日；平季每周 1 次；新公告 24h 内复核 | 404/410 连续 3 次 → 标"源失效"降为历史参考；L1 新公告与旧记录冲突 → **旧记录立即下架** |
| **L2 半官方** | 高校教务处/研究生院、省级教育考试院（jwc.sjtu.edu.cn ✅、www.bjeea.cn ✅） | **只能佐证，不能单独定案**；补全"本校截止/校内选拔"，须回链 L1 | 报名季每周 1 次；平时每月 1 次 | 与 L1 冲突**以 L1 为准**并留记录；需登录或已删除 → 直接摘除 |
| **L3 可信媒体** | 中青在线、上观新闻、省级党媒（www.cyol.com ✅、www.shobserver.com ✅） | **仅作线索，不作事实来源**；须回溯 L1 原文才可发布 | 不主动巡检，被引用时回溯 | 3 个工作日内未找到 L1 原文 → 丢弃 |
| **L4 用户投稿** | 站内「信息有误？」「提交新信源」 | **永久不能成为任何条目的唯一来源**；只触发复核 | 每条 48h 内人工处置 | 48h 无佐证 → 关闭；同一用户 3 次无效 → 降权 |

**硬规则**：confidence 上限由层级锁定——L1 直证 100、L2 ≤75、L3 ≤50、L4 ≤40（不可发布），防止拼凑出虚假高置信度。

> robots.txt 在中国**无法律强制力**，只是"是否善意"的证据。真正的风险来自《反不正当竞争法》第十二条与"实质性替代"判例：**判断标准不是"robots 允许吗"，而是"有没有实质性替代原站的流量与广告价值"**。索引+跳转不构成替代，全文转载+站内阅读构成替代。

**服务条款（ToS）风险**。多数政务与考试类站点不公开可直达的用户协议，本文**未逐站核验条款**（见 §7）；同类站点通行三类限制须预先设防：① 禁止复制、镜像、建镜像站；② 禁止用爬虫批量获取；③ 转载须书面授权。策略是把风险前移：**不复制正文、不做镜像站、控频 0.5 QPS 以下**，并在"关于"页公开抓取策略与联系方式，形成"善意抓取"的证据链。

### 4.2 版权：全文转载 vs 摘要+跳转

《著作权法》第五条将"国家机关的决议、决定、命令和其他具有立法、行政、司法性质的文件"排除在保护外，但**报名通知、大纲、教材目录是否落入该款存在争议**，且大纲常由出版社或组委会享有汇编权。**工程上按"有版权"处理成本最低**：① 标题照录，**正文一律不落地**；② 摘要自写 ≤80 字，只陈述事实要素，不做评论或洗稿；③ 附件只存外链，不镜像不转 CDN；④ 详情页给 canonical 外链；⑤ 版权投诉 24 小时内下架留痕。反例：公告全文入库做站内阅读、PDF 转 HTML、招聘描述整段搬运。

### 4.4 合规设计

**只做索引不做镜像，只给事实不给观点，只导流不闭环。** 四条硬约束：① 库内不存正文全文，只存 title + 自写 summary + source_url + fetched_at + 结构化字段；② 附件只存 URL；③ 招聘模块不设投递动作，仅 rel="nofollow noopener" 外链；④ 抓取器内置 robots 解析与黑名单（ielts/toefl/tiaozhanbei 跳过）。

## 5. 真实性保障机制

**5.1 双源交叉验证**。触发条件：写入 signup_start / signup_end / fee / event_dates。A 级（可自动发布）= L1 原文直证 **且** 至少 1 个独立源时间窗内一致；B 级（人工确认后发布）= 仅 L1 单源；C 级 = 仅 L2/L3/L4，不发布。冲突时**取更晚发布者 + 标 conflict + 强制人工**，不做多数投票。

**5.2 变更 diff 留痕**。每次抓取存 content_hash（正文归一化 SHA-256）与字段快照；不变只更新 last_seen_at；变则生成 Revision，落 field_diff 保留 180 天；关键字段变更**告警并冻结自动发布**。

**5.3 置信度与阈值**。用规则加权而非模型自评（自评不可靠）：

~~~text
confidence = 0.40×来源层级(L1=100,L2=70,L3=45,L4=30)
           + 0.30×抽取方式(规则命中=100,表格解析=85,LLM+字段校验=70,纯LLM=45)
           + 0.20×交叉一致(双源=100,单源=60,冲突=0)
           + 0.10×历史稳定(近12月稳定=100,有波动=50)
~~~

| 置信度 | 处置 |
|---|---|
| ≥85 | 自动发布，标"已核验" |
| 60–84 | 进人工队列，**24h 内**处置，期间显示"待核验"灰色态 |
| <60 | **不发布**，只进候选池 |

## 6. 必须人工确认、绝不能自动化的十类信息

错一次的代价远大于慢一天，以下十类只能人工录入。

1. **报名费用金额**：分省定价、逐年调整、部分科目加收，常藏在附件表里，抽取易错位。
2. **报名起止时间**：CET 明确"各考点报名时间不同"，不存在全国统一时间。
3. **考试日期与批次安排**：可能因政策或突发事件调整、延期。
4. **报考资格与学历/专业限制**：错判一条会误导用户白准备一年。
5. **政策性优惠**：单独划线地区、免试、加分、专项计划，规则复杂逐年改。
6. **竞赛晋级规则、获奖名单、赛区划分**：组委会临时调整多发。
7. **招聘岗位薪资、学历要求、是否校招**：用人单位随时改，快照滞后。
8. **"取消/延期/辟谣/声明"类公告**：误传即为造谣，须人工确认后加急发布。
9. **含个人身份信息的名单**：法律红线，不入库。
10. **考点变更、准考证打印入口开放**：时效极强、常工作日临时通知。

**配套机制**：这些字段在库内打 manual_only=true，抓取器抽到只能写 pending_review 表，永不直更主表。

## 8. 给下游的三条结论

1. **技术侧**：抓取器按「静态优先、浏览器兜底、黑名单硬编码」三层设计；bm.ruankao.org.cn 的省级报名表可作结构化抽取样板，证明官方表格能被规则解析。
2. **产品侧**：/sources 页须真实可用（层级、最近成功抓取时间、失效率），这是"信息可靠"的唯一可验证证据。
3. **评审侧**：最大合规脆弱点不是抓取，是**招聘模块**。不做投递闭环则风险可控；一旦加"一键投递"就变成网络招聘服务，需许可证。
