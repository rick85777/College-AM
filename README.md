# College-AM

> 把散落在 6 个官网里的四六级、计算机等级、教资、软考、数模、国创赛关键日期，收进一份可以订阅的日历。
> 每条都标注**来源链接 / 抓取时间 / 可信等级**。不写"预计"，不猜日期——官方没公布就显示"未公布"。

---

## 这个项目做什么

一个**信息索引**，不是内容站：

| 做 | 不做 |
|---|---|
| 结构化报名/考试/开赛日期，导出 `.ics` 订阅 | ❌ 不转载公告全文 |
| 每条标注来源链接 + 抓取时间 + 可信等级 | ❌ 不镜像 PDF 大纲/职位表 |
| 按**职业出口**划分频道（不是按学院） | ❌ 不做报名代理、不代收费用 |
| **逐省**列出报名时间窗口（信息差的核心） | ❌ 不做站内投递、不接收简历 |
| 招聘**只做外链跳转**，页面上不存在站内申请表单 | ❌ 不代收职位、不做付费发岗、不撮合 |
| 官方原文一键跳转 | ❌ 不做站内投递、不接收简历 |
| 过期条目降级为"已结束"，保留 URL | ❌ 不做 AI 生成正文、不做个性化推荐 |

## 为什么做这个

同一个问题——"我这个专业，未来三个月有哪些证和比赛要报名"——现在要跳 6 个互不相通的官网。

而更隐蔽的痛点是：**"全国统一考试"的报名时间从来不是全国统一的。**

```
2026 年 9 月 全国计算机等级考试（NCRE）
  天津   2026-06-25 09:00 开始报名
  上海   2026-08-31 10:00 才开始报名      ← 相差 67 天
```

只看全国通知，等于什么都没看。这就是本项目把「省级窗口」做成一等公民的原因。

## 快速开始

> 需要 Node.js ≥ 20。**零运行时依赖**——不需要 `npm install`。

```bash
node scripts/validate.mjs    # 校验 data/ 下的所有 JSON
node scripts/test.mjs        # 跑测试（26 个断言）
node scripts/build.mjs       # 生成静态站到 dist/
node scripts/dev.mjs 4173    # 本地预览 http://127.0.0.1:4173

node scripts/fetch.mjs       # 抓取官方源，产出候选变更到 data/review-queue.json
node scripts/audit.mjs       # 审计产物：断链 / .ics 结构 / sitemap / PWA / 390px 溢出

npm run check                # 一条命令跑完全部（校验 + 测试 + 构建 + 审计）
```

## 手机端

响应式是第一层，PWA 是第二层——**不做 App 壳，也不上应用商店**。

| 层 | 做了什么 |
|---|---|
| 响应式 | 移动优先；390px 下 27 个页面**零横向溢出**（`npm run audit` 用无头 Edge 逐页实测） |
| 顶栏 | ≤560px 自动换行：品牌名不折行，导航独立成行并做右侧渐隐提示可滑动 |
| 可安装 | `manifest.webmanifest` + 满版品牌绿图标（192/512，`maskable`）→ 可「添加到主屏幕」，独立窗口打开 |
| 离线 | `sw.js` stale-while-revalidate：先读缓存再后台更新；断网时首页/日历/省级窗口仍可打开 |
| 日期订阅 | 每个条目/频道/全省份都有 `.ics`，iOS 日历、Android、Outlook 均可直接订阅 |

> 为什么不做 App：一个一年只需要打开 ≤40 天的工具，装 App 是纯负担。PWA 让"加到桌面"的成本降到一次点击，也不占用户存储。

### 关于桌面端

**不做 Electron/Tauri 封装**，但产物本身可以直接双击打开——`dist/` 是全相对路径的纯静态文件，不依赖服务器。

想把它固定到桌面：

```powershell
# Windows：在桌面建一个快捷方式，指向 dist/index.html
$s = (New-Object -ComObject WScript.Shell).CreateShortcut("$env:USERPROFILE\Desktop\College-AM.lnk")
$s.TargetPath = "$PWD\dist\index.html"
$s.Save()
```

用浏览器的「创建应用快捷方式」（Chrome/Edge 均支持），得到的是一个无地址栏的独立窗口，效果与装一个桌面应用接近，但**包体是你已经下载的这几个 KB 的 HTML**，不是 150MB 的 Chromium。

> 为什么不打包：Tauri/Electron 的成本是现在的 2 倍以上，包体 5–150MB，Windows/macOS 还要签名，而这个产品的使用场景是"手机上查截止日"——桌面端连第二入口都算不上。PWA + 快捷方式已经覆盖"想在电脑上常驻"的那一小部分需求。

## 数据模型（三条硬规则）

### 1. 一个 Program 可以有多个 Edition

```json
{
  "id": "cet",
  "editions": [
    { "id": "cet-2026-h1", "year": 2026, "round": "h1", ... },
    { "id": "cet-2026-h2", "year": 2026, "round": "h2", ... }
  ]
}
```

`round` **必须是 `h1 / h2 / annual / special`**，不能用 `main`——四六级、NCRE、教资都是一年两轮，用 `main` 会导致唯一键冲突（这是红队评审抓出的 M6）。

### 2. 日期用 `milestones`，不是四个扁平字段

一个届次往往有多个节点（口试/笔试/准考证打印/报名开始）：

```json
"milestones": [
  { "label": "笔试报名开始", "date": "2026-09-02", "kind": "signup" },
  { "label": "笔试 CET",     "date": "2026-12-12", "kind": "event" }
]
```

- `kind`: `signup`（报名相关）/ `event`（考试/比赛）/ `other`（准考证打印等）
- 日期必须是 `YYYY-MM-DD`，**"预计 3 月"这类模糊值会被校验器拒绝**
- 官方没公布就**不写**，UI 显示"未公布"——绝不推算

### 3. 有些字段永远不能自动发布

`lib/schema.mjs` 里的 `MANUAL_ONLY_FIELDS`：

```js
signupStart, signupEnd, eventStart, eventEnd, feeCny, feeNote
```

这些字段**只能人工确认后写入**，与置信度分数完全解耦。原因见 `docs/College-AM-可行性分析报告.md` §4.3。

## 可信等级（L1–L4）

| 等级 | 定义 | 能不能单独定案 |
|---|---|---|
| **L1 官方** | 主办方/主管部委一手发布口 | ✅ 唯一可以直接支撑"报名时间/费用/考试日期"的层级 |
| **L2 半官方** | 高校教务处、省级考试院 | ❌ 只能佐证，必须回链 L1 |
| **L3 媒体** | 可信媒体报道 | ❌ 仅作线索 |
| **L4 投稿** | 用户纠错 | ❌ **永不作为唯一来源**，且不得直接发布（校验器会报错） |

`reviewState` 四态：`pending` / `auto_published` / `human_approved` / `rejected`。
**只有 `human_approved` 和 `auto_published` 会出现在站点上。**

## 已知限制

1. **覆盖不完整**：挑战杯、雅思、托福、CPA 报名系统、研招目录这些要么 robots 全站禁抓，要么是 SPA/需登录。**这类源只能人工录入，且会持续滞后。**
2. **自动抓取只有 1 个源**：`scripts/fetch.mjs` 支持 bm.ruankao.org.cn（静态表格）。其余源仍是人工。抓取器**只产出候选变更，不改主数据**——报名时间属于 `manual_only` 字段。
3. **报告里说"80 元/月"是抓取管道的估算成本**，当前版本成本为 0（纯静态站）。
